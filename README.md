> ⚠️ 仅限个人设备、自己安装的应用使用。保活会让应用持续占用内存与电量，请勿用于追踪、监控他人设备。

## 安装

在 LSPosed Manager 中搜索「进程保活」安装，或从
[Releases](https://github.com/Xposed-Modules-Repo/io.github.guys222.processkeepalive/releases) 下载最新 APK
（如 `PKA-v3.5.2-build4363.apk`，已用项目专用 keystore 签名，可直接覆盖安装）。

每个版本都发**两个包**，功能完全一样：

- `PKA-v<版本>-build<号>.apk` —— 正式包，装给所有人；
- `PKA-v<版本>-build<号>-debug.apk` —— 测试包，**遇到问题请装这个**：白屏、卡死（ANR）、拉不起来时
  它会自动把现场存进 `/data/system/pka_hook.log`，导诊断包时一并带走。两者同签名，可互覆盖。

**装完必须重启手机** —— 钩子跑在系统框架里，不重启加载的还是旧代码。

启用后**必须**在 LSPosed 中把作用域勾上「**系统框架（android）**」——所有钩子都注入
`system_server`，不勾这一项模块不工作。

> 可选：同时勾选「本模块」仅用于 App 主页「模块激活状态」的实时检测，不勾不影响保活。

## 它能做什么

| 能力 | 说明 | 默认 |
| --- | --- | --- |
| 降低 OOM Adj | 把目标进程优先级压低到「可见级」，LMK 不优先杀它 | 开 |
| 阻止强制停止 | 拦截 `forceStopPackage`，设置里的「强行停止」失效（**保进程**） | 开 |
| 阻止后台杀死 | 拦截 `killBackgroundProcesses`（**保进程**） | 开 |
| 防止系统冻结 | 拦截 app freezer，避免进程被冻结后直接 SIGKILL（**保进程**） | 开 |
| 强力模式 | 拦截 `ProcessRecord.kill` / `killPackageProcessesLocked`（**保进程·激进**） | 关 |
| 常驻实验 | 把目标进程标记为 `persistent`，被杀后自动重启（**保进程·兜底**） | 关 |
| 消息保活 | Doze/Standby 豁免 + 伪装前台防断连（**保进程**，顺带让界面不被回收） | 关 |
| 页面保活 | 把进程状态伪装为 `BOUND_TOP` / `FOREGROUND_SERVICE`，系统不回收其 Activity（**保页面**） | 关 |
| 开机自启动 | 重启后自动拉起已勾选的应用（system_server 内拉起，绕过后台限制） | 关 |
| 三道防线 | 进程死亡后按「服务 → Provider → 界面」依次尝试拉回，界面拉起后自动退回后台 | 开 |

> **「保进程」和「保页面」是两件事。**
> 除「页面保活」外，所有开关只保证**进程不被杀**——应用回到前台时，界面（Activity）仍可能被
> 系统回收并重新加载，这是 Android 的正常行为。
>
> 「页面保活」通过把进程状态伪装成前台（`BOUND_TOP` / `FOREGROUND_SERVICE`）来阻止系统回收 Activity，**只对"由系统主动回收页面"
> 的 ROM 有效**。若应用自己主动调用了 `finish()` 重建界面（如部分 App 检测到后台超时后主动
> 重启自己的页面），框架层面拦不住，此时页面依然会重载。页面能否完整恢复也取决于应用自身
> 有没有保存状态。

## 原理（钩子点）

全部注入 `system_server`（包名 `android`）：

- `ActivityManagerService.forceStopPackage`
- `ActivityManagerService.killBackgroundProcesses`
- `ActivityManagerService.killPackageProcessesLocked`
- `OomAdjuster.computeOomAdjLocked`（Android 11+；老版本回退 `updateOomAdjLocked`）
- `ProcessRecord.kill`
- `ActivityManagerService.newProcessRecordLocked`（常驻实验）
- `ActivityManagerService.finishBooting`（开机自启动）

OOM Adj 只「下调、不上调」：绝不会把正在前台运行的进程优先级调高，避免误伤。

## 重要提示

- **保活不影响应用更新**（v3.3.0 起）：安装/更新前系统必然调用 `forceStopPackage`，
  模块已对安装、替换、卸载以及 root/shell 调用自动放行，不会再出现「保活后装不上新版」。
- **LineageOS 本身不像 MIUI/ColorOS 那样激进杀后台**，本模块主要解决「内存紧张时被 LMK 杀掉」
  和「被强行停止」两类场景，效果不像在国产 ROM 上那么戏剧化。
- **常驻实验有风险**：可能让应用在卸载/更新时异常、崩溃后无限重启、增加耗电，默认关闭。
- **常驻通知需要通知权限**：Android 13+ 首次开启会申请 `POST_NOTIFICATIONS`。
- **Doze/待机**：对开启「消息保活」的应用会自动豁免省电白名单与 App Standby 限流。
- 修改任意设置后约 30 秒自动热刷新，无需重启；长时间不生效再重启系统。

## 验证

```bash
adb logcat -s ProcessKeepAlive                 # 查看模块日志
adb shell "ps -A | grep com.example.app"       # 确认进程存活
adb shell "cat /proc/<pid>/oom_score_adj"      # 值越低越不容易被杀
```

## 更新日志

### v3.5.2（build 4363）

**修复白屏** —— 页面保活会拦下「页面切后台」「页面被结束」，前提是「记录还在，页面就能原样回来」。
但进程被杀之后，这条记录就只剩空壳：记录还挂在系统里，却没有任何进程能往它的窗口里画东西。
用户点图标时系统复用的正是它 —— 窗口建出来、内容画不出来，**于是白屏**，直到应用自己重建一遍
（就是那个「白屏然后首页刷新」）。没被杀过的应用不会这样，因为记录不是空壳。
现在页面保活只保**活着的进程**的页面，宿主进程一旦不在，记录一律放行销毁。

**修复「补拉之后应用赖在前台不走」** —— 上一版的保护条件里有一条「界面已就绪就跳过」，
而等待界面就绪的循环恰恰是「就绪才跳出」，同一条判据在同一次调用里恒为真，
于是界面一画出来就永远不送回后台。现在只看两件只有用户才能产生的事实：
拉起**之前**它是否已在前台、它出现**之后**用户是否碰过屏幕。

**第 4 路拉起（AMS 直拉）** —— 在 Android 17 上一直空转：方法找错了类（`startProcessLocked`
在 `ProcessList` 上），参数也是瞎填的（引用类型全塞 null，必然调不通）。现在按真实签名填参；
本机确实不支持时只记一行「不适用」，不再每几秒重试。

**日志体积** —— 防冻分档原来每 20 次一条、每条罗列上百个包名，把日志撑到几 MB。
现在按原因汇总、10 分钟一条。

**debug 包新增「卡死」抓现场** —— 之前三个自动抓点全是为白屏选的，应用 ANR（卡死）时一个都不触发。
现在挂了 `AMS.appNotResponding`，目标应用一 ANR 就自动存主线程栈 / CPU / 内存 / 系统 ANR 记录。

### v3.5.0（build 4232）
**新增功能**

- **三防线按应用覆盖**：开机拉起 / 死亡补拉 / 轮询兜底现在可以逐个应用单独开关，未单独设过的继续跟随全局默认值。分身与主包完全独立，互不影响
- **拉起后夭折事件**：拉起指令发出后复查途中再次死亡的，事件流会单独记一条「拉起后夭折 · 第X防线（第N次）」，不再静默失败
- **轮询间隔可调**：轮询 4 / 6 / 8 秒四档，越短越灵敏也越耗电
- **死亡判定轮数可调**：连续缺席 1~5 轮算死亡，默认 2 轮；带常驻标记的托底 / 核心级目标固定 1 轮
- **噪音闸**：三道防线全关的目标不再产生事件记录，事件流只保留真正需要关注的
- **「起来就死」自动静音**：连续 3 次拉起后存活不足 30 秒，暂停记录该类事件；恢复正常存活后自动解除
- **守护事件独立成页**：事件从主页底部拆出成独立页签，支持按类型筛选
- **终止免拉永久生效**：手动划掉卡片 / 强停 / 一键清理后不再补拉，不会在 60 秒后自己又拉回来；仅当你主动重新打开该应用才恢复。事件流会记一条「暂停补拉」留痕

**Bug 修复**

- **主页显示拉起成功、点开是冷启动**：原先判定标准是「包内有任意进程存活」，而通过 Provider 拉起时经常只有 `:remote`、`.fp` 这类子进程起来，主进程并未启动却被记为成功。现在改为主进程为准，仅子进程存活记为「拉起不完整」并继续补拉
- **拉起后闪一下就没、之后无人处理**：原先拉起指令发出瞬间就记成功，冷启动那几秒的空窗里被杀没有任何人察觉。现在指令发出只登记待确认，由三轮复查（5s / 8s / 12s）确认主进程连续存活后才最终落成功
- **被杀一次后必须手动点桌面才恢复**：同一原因，主进程不存在时收不到死亡回调，第一防线静默失效。随主进程判定一并修复，链路不再中断
- **给分身关掉的防线被主包设置覆盖**：分身键解析不到 userId 时会回退去读主包配置，导致分身的独立设置被主包覆盖。现在两者完全独立，不做回退
- **暂停保活实际不生效**：被暂停的包此前只是从列表里消失，模块侧照常补拉、拦截、记事件。现在下发时直接剔除，模块读不到就不动它
- **手动划掉的目标 60 秒后又被拉回来**：旧实现把用户终止豁免限为 60 秒，超时自动撤销。现在豁免永久有效，只有你重新打开应用才恢复补拉

**界面优化**

- 整体重新排版，开关开启 / 关闭状态的视觉区分加强
- 设置页分区行、说明文字、问号组件的对齐与间距统一
- 暂停保活管理改为弹窗，列表补上应用图标、状态副标题与分隔线

- 页面保活覆盖状态机路径：此前只拦「被遮挡」两条路径，部分应用走状态机直接路径，现补上三条入口，并保留「用户主动退出不拦」。

**网络与兼容性**

- 下载卡死自动恢复：检测到「有活跃连接但 32 秒零流量」时注入一次网络恢复事件，逼应用重建连接。
- WiFi 高性能锁：联网期间持有，空闲释放。
- 修复 Android 17 上 trimSuppress 被误判「不适用」：类解析改为「类在且方法在」，方法搬家可回落到备选类。

**性能**

- 高频路径接上进程缓存：非目标进程一次查表返回，不再逐个反射。
- 新增设备分档（CPU 核数 + 内存）：自动调整心跳与巡检频率。
- VMA 看护在低端机型默认关闭；找进程改走记账，900 次文件读降为 3 次。
